## 二、今天的关键发现

### 1. N08 是"间歇性真实偏差"，不是误报（重要）

| 轮次 | N08 结果 | 它用的标题 |
|---|---|---|
| 10-13 | 骨架、安全事项 **FAIL** | `# 角色`（**一级标题**）|
| 10-14 | 全部 **OK** | `## 角色`（符合要求）|

**结论**：模型对提示词里「使用 Markdown 二级标题」这条规则**遵守不稳定**——**这是系统的真实（轻度）缺陷，不是检查器的问题**。

**方法论收获**：**单次评测看不出这种问题，只有把两轮数据对比才能发现。** 同一个 FAIL，可能是误报（N09），也可能是真缺陷（N08），**必须人工核对原文才能定性**。

**处理方向（尚未决策）**：① 提示词里强化"必须二级标题"；② 检查器放宽到 1~3 级标题。**建议二选一，不要两边都放松。**

### 2. 「示例」段存在排版缺陷（新发现，待修）

用户看输出时发现：生成 Prompt 的「示例」段和正文**同一种排版**，没有视觉边界，难以分辨哪里是示例。

**根本原因**：系统提示词要求"整体放进一个 Markdown 代码块"，外层已占用 ` ``` ` → **内层示例无法再用 ` ``` `（会提前结束外层围栏）**，模型只能退化成裸文本。

**修法（待执行）**：
- 外层改用**四个反引号**包裹，内层示例就能安全用三个反引号
- 并在「示例」段明确标注"输入 / 输出"+ 加视觉分隔

**建议记入 `TODO.md` 的 M4「质量类检查项」**：示例段是否有明确边界。

## 三、今天踩过的坑（速查）

| 现象 | 原因 | 解法 |
|---|---|---|
| `'''...'''` 内容出现在 Streamlit 页面上 | 三引号**不是注释**，是字符串；Streamlit 的 **magic** 会把顶层裸表达式自动渲染 | 注释用 `#`（多行用 `Ctrl + /`）|
| `st.button(st.write('点了'))` 无效 | `st.button` 的参数是**按钮文字**；`st.write` 会立刻执行并返回 `None` | `if st.button('生成'):` 内部再写要做的事 |
| 页面一打开 / 每次交互都调 API | 昂贵逻辑写在**顶层** → 每次重跑都执行 | 把生成逻辑放进 `if st.button(...)` 内部 |
| `st.write(type(obj))` 吐出一大篇文档 | LangChain 的类把**签名 + docstring + 方法列表**写进了 `repr` | 打 `type(obj).__name__`，或改打更有意义的检查（条数 / 模型名）|
| 点按钮的结果改输入框后就消失 | 结果没被"保存"，只是那次重跑恰好显示了 | 用 `st.session_state` 存起来 |
| 新手最易混：`Rerun` / `Clear cache` / F5 | 三者清的东西不同 | Rerun 只重跑（保留 session_state）；Clear cache 清缓存（会重新加载模型）；F5 通常开新会话；**最省心是重启 streamlit** |
| `Ctrl + /` 无法多行注释 | 焦点不在编辑器 / 中文输入法吞键 | 切英文输入法、点一下代码区；或用 `Alt` + 拖动多光标 |

## 五、今天学会的 Streamlit 概念

| 概念 | 一句话 |
|---|---|
| 运行模型 | **每次交互，整个脚本从头重跑一遍** |
| `@st.cache_resource` | 缓存**重量级对象**（模型、向量库、连接）→ 返回同一对象 |
| `@st.cache_data` | 缓存**数据**（列表、DataFrame）→ 每次给副本，避免互相影响 |
| `st.session_state` | **跨重跑保留的字典**；写入用 `st.session_state.键 = 值` |
| `if st.button(...)` | 只在该按钮被点击的**那一次重跑**为真 |
| `with st.spinner(...)` | spinner 必须**包住**耗时操作才有意义 |
| magic | 顶层**裸表达式**会被自动 `st.write` 渲染 → 所以三引号会显示 |
| 启动方式 | `streamlit run src/xxx.py`（**不是 `python`**）|
